## Conflict hot-spots (merge-with-main resolutions)
| File | Why it collides | Resolution |
|------|-----------------|------------|
| `package-lock.json` | Renovate and features churn it | **regenerate** (`npm install`), don't hand-merge |
| `public/data/catalogue.json`, `public/data/museum.json`, `public/media/atlas.json`, `public/assets/CREDITS.md` | generated by `fetch` / `derive` / `media` / `fetch-assets` | **regenerate** with the matching `npm run` script |
| `docs/plan/*.svg` | generated from `src/plan/musee.ts` | **regenerate** (`npm run plan:svg`) |
| `docs/superpowers/` specs and plans | parallel work documents itself | **union** |
- **Rule of thumb:** union additive files, regenerate derived files; same-logic-both-sides is a real
  semantic conflict — understand both intents or stop.

## Architecture grain / invariants (shape implementation plans to these)
- `src/plan/musee.ts` is the only source of the building: 3D, collisions and minimap derive from it,
  never the reverse. The building is fixed; only theme assignment and hanging are generated nightly.
- `src/plan/` and `src/domain/` stay free of three and React imports, testable without WebGL; any
  decision lives there, `src/scene/` only renders.
- Every plan change passes `checkPlan` (`src/plan/rules.ts`) and regenerates `docs/plan/`.
- The editor never ships: it stays behind `import.meta.env.DEV` via a dynamic import (`src/editor/EditorMount.tsx`).
- The old generated building (`src/domain/layout.ts`, `derive.ts`, `builders/`) is being replaced by the plan.
